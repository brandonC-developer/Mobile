# Data Model

> **Status:** Approved by the Owner in commit `a1bc3ba` (2026-11-02); drafted by the agent. Logical model only; physical types are chosen at implementation with Room (ADR-0002). The backup file (ADR-0004) mirrors these entities.

## Overview
Three stored entities and one settings record. Collections and reminders are **not stored**: they are computed from rentals and settings (FR-013, FR-021).

```
Tenant 1 ──< Rental >── 1 Property
```

A tenant and a property each have at most one active rental at a time (FR-008). A tenant may have many ended rentals. A property may appear in many rentals over time.

## Entities

### ENT-001 — Property
- **Status:** Approved
- **Origin:** FR-001 · FR-002 · FR-003
- **Description:** A unit the landlord rents out. Never deleted.

| Attribute | Logical type | Required | Rules / origin |
|-----------|--------------|----------|----------------|
| id | integer | yes | Unique, generated by the app |
| name | text | yes | Not empty (AC-FR-001-2) |
| description | text | no | FR-001 |

- **Relationships:** referenced by zero or more Rental.
- **Personal data:** no, as far as the landlord keeps it neutral; the description is free text and could hold personal data (see DOC-SEC).
- **Lifecycle:** created by the landlord, editable at any time, never deleted. A property with no active rental is free (FR-011).

### ENT-002 — Tenant
- **Status:** Approved
- **Origin:** FR-004 · FR-005 · FR-006
- **Description:** A person who represents a household that rents a property.

| Attribute | Logical type | Required | Rules / origin |
|-----------|--------------|----------|----------------|
| id | integer | yes | Unique, generated by the app |
| fullName | text | yes | Not empty (AC-FR-004-2) |
| phone | text | no | Used for WhatsApp and call (FR-025, FR-026). Stored as typed; +506 is added for WhatsApp when no country code is present (OI-043) |

- **Relationships:** referenced by zero or more Rental.
- **Personal data:** yes (name, phone).
- **Lifecycle:** created, editable at any time, deleted with all its rentals after confirmation (FR-006).

### ENT-003 — Rental
- **Status:** Approved
- **Origin:** FR-007 to FR-013
- **Description:** The agreement that links one tenant to one property with an amount and a payment day.

| Attribute | Logical type | Required | Rules / origin |
|-----------|--------------|----------|----------------|
| id | integer | yes | Unique, generated by the app |
| tenantId | reference to ENT-002 | yes | Fixed after creation (FR-009) |
| propertyId | reference to ENT-001 | yes | Fixed after creation (FR-009) |
| amount | integer, whole colones | yes | Greater than zero (AC-FR-007-2, NFR-008) |
| paymentDay | integer 1 to 31 | yes | Last day of the month when missing (FR-013) |
| endDate | date | no | Not earlier than today when set (AC-FR-007-3). Empty means open-ended |

- **Relationships:** exactly one tenant and one property.
- **Personal data:** indirectly, through the tenant.
- **Lifecycle:** created; amount, paymentDay and endDate editable (FR-010); ended by setting endDate (FR-011); kept until its tenant is deleted; may be deleted alone (FR-012).
- **Derived (not stored):** *active* means no endDate, or endDate not before today. Collection dates per month follow FR-013 and stop after endDate. The end-date day itself still generates a collection (OI-043).

### ENT-004 — Settings
- **Status:** Approved
- **Origin:** FR-018 · FR-019
- **Description:** One record with the reminder choices.

| Attribute | Logical type | Required | Rules / origin |
|-----------|--------------|----------|----------------|
| remindThreeDaysBefore | yes/no | yes | FR-018 |
| remindTwoDaysBefore | yes/no | yes | FR-018 |
| remindOneDayBefore | yes/no | yes | FR-018 |
| remindSameDay | yes/no | yes | FR-018 |
| reminderTime | time of day | yes | One time for all reminders (FR-019) |

- **Relationships:** none.
- **Personal data:** no.
- **Lifecycle:** exists from first launch with defaults (defaults: 3 days, 1 day and same day on, 2 days off, 08:00 (OI-043)); editable at any time; replaced by import (FR-028).

## Integrity rules
- A rental cannot exist without its tenant and its property; deleting a tenant deletes its rentals in one transaction (FR-006, ADR-0002).
- At most one active rental per property and per tenant (FR-008). Enforced by the app in one transaction with the check; not by a database constraint alone because "active" depends on the current date.
- Amounts are integers (NFR-008). No statuses are stored (FR-014).

## Not stored
Collections, reminders, week totals, the free/occupied state of a property.

## Open points
None from OI-043: defaults, phone format and end-date boundary were decided by the Owner.
